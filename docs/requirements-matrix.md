## 精确边界

- “经过电脑 Codex 的行为”在技术上只能覆盖**产生模型 API 请求且请求经过公司网关**的行为。纯本地文件读取、Shell 命令或其他没有访问模型 API 的动作不会到达网关。
- MVP 使用单个部署级 `GATEWAY_BEARER_TOKEN`，满足公司统一凭据入口，但没有逐员工 Key 发放、轮换、撤销或用量归属后台。
- Skill 是声明式指令模块，不执行员工提交的任意代码。
- `/v1/chat/completions` 提供兼容转发，但主要注入路径和 Codex 配置目标是 Responses API `/v1/responses`。
- 接真实 OpenAI 前，部署者需要配置合法上游地址、模型和密钥；仓库不包含也不会读取员工本机的真实 API Key。

## 端到端验收路径

1. 管理员登录，创建常驻公司 Prompt 或 Skill，并按需创建带 Skill 的 Agent。
2. 员工登录，创建个人能力并提交。
3. 管理员在审核队列批准，确认公司能力库出现带作者归属的副本。
4. 员工把本地 Codex 的 `base_url` 指向公司网关 `/v1`，把公司网关凭据放在约定环境变量中。
5. 发起 Codex 模型请求；验证上游收到的 `instructions` 中，公司能力位于调用方原始指令之前。
6. 验证上游 JSON 经安全处理或 SSE 经字节流转发后返回 Codex。
